# 跨设备同步（自带通道）

> 一句话：drawpaper 官方**不提供任何服务器**。跨设备同步用哪条通道，完全由你自己选、自己搭——
> 官方只负责在你选好的文件夹 / WebDAV 地址里读写 `.kbnote` 文件，不中转、不接触、不存储你的任何数据。
>
> 本文面向普通用户，讲清楚两件事：**怎么配**、**冲突了怎么办**。

## 1. 总览与隐私模型

| 你担心的 | 实际情况 |
|---|---|
| 官方有云服务器吗？ | **没有。** 没有账号体系，没有官方云盘，没有官方同步服务。 |
| 同步数据走哪里？ | 只走你自己掌控的通道：你设备之间的 Syncthing P2P 直连，或你自己的 WebDAV 服务器（Nextcloud / 坚果云 / 自建 NAS）。 |
| 凭据存在哪？ | WebDAV 的 base URL / 用户名 / 密码只存在**当前浏览器的 localStorage** 里，与 AI 辅助的 endpoint / key 同级，不上传、不离开本机。 |
| 不配通道会偷偷联网吗？ | **不会。** 未配置任何同步通道时，同步模块完全不运行，app 不发任何同步相关的网络请求（你自配的 AI endpoint 除外）。 |

**两种通道二选一，互斥**（见 §4.4）：

| 通道 | 适合谁 | 自动化程度 |
|---|---|---|
| **方案一：同步盘文件夹**（推荐） | 想零配置服务器、两台以上设备互相同步 | 全自动（浏览器支持 File System Access 时） |
| **方案二：WebDAV** | 已有 Nextcloud / 坚果云 / NAS，或想借助现有云盘中转 | 半自动（手动触发 / 可选定时轮询） |

## 2. 方案一（推荐）：同步盘 watched 文件夹

### 2.1 它是怎么工作的

原理很简单：drawpaper 把你的每篇文档导出成一个 `.kbnote` 文件，放在**一个你指定的本地文件夹**里；
这个文件夹本身是 Syncthing / iCloud Drive / OneDrive / Dropbox 的同步目录，由同步软件负责在设备间搬运文件。
drawpaper 不关心、也不参与搬运过程——它只做两件事：

1. **写出去**：你在 app 里编辑，停顿防抖后自动把 `.kbnote` 写进这个文件夹（图片 / 附件存到文件夹下的资产子目录，按内容 hash 命名去重——同一张图在多篇文档里只存一份）。
2. **收进来**：app 前台运行时定期扫描这个文件夹的文件清单（文件名 + 大小 + 修改时间），页面从后台切回前台时再立刻扫一次；发现外部新增 / 变化的 `.kbnote` 就拉进来合并（合并前自动拍快照，见 §4）。

### 2.2 Windows 配置（Syncthing，推荐起点）

Syncthing 是开源、免费、设备间点对点直连的文件同步工具，不经过任何第三方服务器。

1. 到 [syncthing.net](https://syncthing.net/) 下载 Windows 版，解压后运行 `syncthing.exe`。
2. 它会自动打开管理页 `http://127.0.0.1:8384`。
3. **添加文件夹**：点「Add Folder」，Folder Label 随意（如 `drawpaper-sync`），Folder Path 选一个空目录（如 `D:\drawpaper-sync`）。
4. **添加远程设备**：点「Add Remote Device」，填入另一台设备的 Device ID（在那台设备的 Syncthing 管理页「Actions → Show ID」里可以看到，二维码亦可扫码）。
5. 在另一台设备上会弹出接受提示，确认后勾选要共享的 `drawpaper-sync` 文件夹，**两端都确认后同步才开始**。
6. 确认 Syncthing 管理页里该文件夹状态为「Up to Date」。

### 2.3 Android 平板配置（Syncthing app + 文件夹通道）

1. 在平板 F-Droid（推荐）或 Google Play 安装 **Syncthing** app。
2. 打开 Syncthing app → 底部「+」→「Add folder」，选一个你有权限访问的空目录（如 `/storage/emulated/0/Download/drawpaper-sync`）。
3. 「+」→「Add device」，扫码或手填电脑端 Syncthing 的 Device ID。
4. 在**电脑端** Syncthing 管理页接受这台新设备，并在文件夹共享设置里勾选这台平板。
5. 保持 Syncthing app 在后台运行；建议在系统电池优化里把它加白名单，否则系统可能杀掉它导致不同步。

### 2.4 iCloud Drive / OneDrive / Dropbox 目录（同理）

不想装 Syncthing 也可以——任何「在本地有一份镜像目录」的云盘都行：

- **macOS**：直接选 iCloud Drive 里的某个文件夹；
- **Windows**：选 OneDrive 本地目录（如 `C:\Users\<你>\OneDrive\drawpaper-sync`）；
- **Dropbox**：选 Dropbox 本地同步目录下的子文件夹。

在 drawpaper 里选择同步目录时，选这些云盘的本地镜像文件夹即可，原理与 §2.1 完全相同。

### 2.5 在 app 里选择同步目录

> 以下按钮文案为暂定名，以你实际版本的 UI 为准。

1. 打开 drawpaper → 进入「设置」→「同步」。
2. 通道类型选「同步文件夹」。
3. 点「选择同步目录」，在系统目录选择器中选中上面准备好的文件夹（`drawpaper-sync` 或云盘镜像目录）。
4. 浏览器会请求该目录的读写授权，确认后即启用。之后：
   - 本地已有文档会自动导出进该目录；
   - 另一端设备新放进来的 `.kbnote` 会被检测到并合并。

### 2.6 自动导出与外部变更合并行为

- **自动导出**：编辑停顿防抖后自动写出 `.kbnote`，不打断输入；保存状态提示会显示「已导出到同步文件夹」。
- **外部变更检测**：前台定期扫描 + 切回前台时立即扫描；发现变化后拉取合并，合并前自动拍一份快照（可在历史里回退）。
- **合并**：按 §4 的自动合并规则处理；无法自动取舍时生成冲突副本（§4.2），顶部弹横幅提醒，**不会静默覆盖任何一边**。

### 2.7 Safari / Firefox 的手动降级

Safari 与 Firefox **不支持** File System Access API（即无法让网页直接读写一个本地文件夹），自动通道不可用，降级为手动搬运：

- **导出**：在 app 里把文档「导出为 .kbnote」，浏览器下载到「下载」文件夹，你再手动把它拖进同步文件夹。
- **导入**：另一端设备从同步文件夹里拿到新版 `.kbnote` 后，在 app 里用「打开 .kbnote」选入。
- 这是纯手动、单向、无自动检测的方式，适合临时应急；日常多设备使用推荐在 Chromium 内核浏览器（Chrome / Edge）或 Windows Tauri 桌面壳里跑全自动通道。

## 3. 方案二：WebDAV

### 3.1 适用场景

你已经有一台常年在线的 WebDAV 服务器（自己的 Nextcloud、坚果云账号、或 NAS），想让多台设备通过它中转。
drawpaper 不运行任何中间服务——它只是你的 WebDAV 服务器的一个普通客户端。

### 3.2 各家 base URL 示例

| 服务 | base URL 示例 | 备注 |
|---|---|---|
| **Nextcloud** | `https://cloud.example.com/remote.php/dav/files/你的用户名/` | 路径必须带 `/remote.php/dav/files/用户名/` 后缀 |
| **坚果云** | `https://dav.jianguoyun.com/dav/` | 密码**不要用网页登录密码**，见下 |
| **群晖 NAS（DSM）** | `https://你的NAS地址:5006/`（HTTPS）或 `http://192.168.x.x:5005/`（HTTP） | 先在 DSM「控制面板 → 应用程序 → WebDAV」里启用；端口以 NAS 设置为准 |
| **威联通 NAS（QTS）** | `http://192.168.x.x:8080/` | 先在 QTS「控制台 → Web 服务器 → WebDAV」里启用；端口以 NAS 设置为准 |

**坚果云第三方应用密码（重要）**：坚果云为了保护账号，要求第三方客户端使用单独的应用密码：
登录坚果云网页端 → 右上「账户信息」→「安全」→「第三方应用管理」→「添加应用」，给它起个名字（如 `drawpaper`），
生成一串专用密码——在 drawpaper 里填**这串密码**，而不是你的网页登录密码。

### 3.3 填写 base URL / 用户名 / 密码

在「设置 → 同步」里把通道类型切到「WebDAV」，填三项：

- **base URL**：照 §3.2 的例子填，结尾通常带 `/`；
- **用户名**：WebDAV 服务器的登录用户名（坚果云即账号邮箱）；
- **密码**：登录密码，或坚果云的第三方应用密码。

保存后点「立即同步」验证连通性。

### 3.4 http 明文警告是什么意思

如果你填的 base URL 是 `http://`（而不是 `https://`），app 会弹出一条黄色安全警告，含义是：

> 从现在起，你的 WebDAV 用户名密码和每篇文档内容都会以**不加密的明文**在网络上传输——
> 同一个 Wi-Fi / 局域网下的任何人都可以抓包看到。

- 仅在**可信的局域网**里（家里 / 办公室、无陌生设备）可以接受这个警告继续；
- 凡是要走公网的地址，务必用 `https://`（NAS 需要自备证书或套一层反向代理）。

### 3.5 手动同步与定时轮询

- **手动**：每次同步都由你点「立即同步」触发（上传本地新变更 + 拉取远端变更）。
- **定时轮询**：默认**关闭**。需要时可在设置里开启，最小间隔 **5 分钟**（间隔过短会频繁请求服务器，不建议）。

### 3.6 401 / 网络错误会怎样

- **401 认证失败**：右下角 toast 提示「认证失败，请检查用户名 / 密码」。**本地数据不受任何影响**，改对凭据后再点「立即同步」即可。
- **网络错误 / 超时**：toast 提示「无法连接服务器」，同样**本地文档不丢、不改、不回滚**。网络恢复后手动再同步。

## 4. 冲突是怎么处理的

### 4.1 自动合并（用户视角）

两端同时编辑时，大多数情况你感知不到——app 复用了同浏览器多标签协作的合并语义：

- 每次编辑都带一个**逻辑时钟**，谁后写谁生效（字段级最后写入胜）；
- 你删的块带**墓碑**标记，另一端即使还在改它，也以「删除」为准，不会复活；
- 两个人改的是不同的块 / 不同的字段，两边改动**都保留**。

### 4.2 什么时候会冒出 `.conflicted-` 副本

只有当两端对**同一处结构**做出互相矛盾、无法自动取舍的修改时（例如同一块在两端被拖进了两个不同的父块，
或两篇文档在两端各自分叉演化），app 才不会替你猜——它会：

- 把较新的那份快照作为主文档保留；
- 把另一端的另一份原样存为冲突副本：`《文档名》.conflicted-《时间》.kbnote`
  （例如 `读书笔记.conflicted-20261006-143022.kbnote`）；
- 顶部弹出横幅告诉你「本次同步有未决冲突，已保留副本」。

**.conflicted 文件不是错误，是保险**——它保证任何一端的修改都不会被悄悄吃掉。

### 4.3 怎么打开副本、比对、取舍

1. 在同步文件夹（或 WebDAV 根目录）里找到 `《文档名》.conflicted-《时间》.kbnote`。
2. 在 drawpaper 里用「打开 .kbnote」打开它，与主文档并排对照（可开两个浏览器窗口 / 两个标签页）。
3. 把要保留的内容补回主文档；确认无用后，**手动删除**这个 conflicted 副本（删掉即从同步文件夹移除，各端一致）。

### 4.4 多通道互斥

**同一时间只启用一个同步通道**：要么「同步文件夹」，要么「WebDAV」，不能同时开。
两个通道同时跑会导致同一份文档被往两个地方各导出一遍、互相制造重复副本。
切换通道前，先在设置里停用当前通道。

## 5. 故障排查清单

| 现象 | 排查与处理 |
|---|---|
| 两端怎么都不同步 | ① 设置里确认通道已「启用」；② 同步文件夹方案：Syncthing 两端都在线、文件夹已互相共享且状态为 Up to Date；③ WebDAV：点「立即同步」看 toast 报什么错 |
| 浏览器重启后要求重新选目录 | File System Access 目录授权随站点保存，但部分浏览器 / 系统升级后会要求重新授权一次，重选同一个目录即可 |
| 冒出很多 `.conflicted-` 副本 | 两端离线期间各自改了同一文档——预期行为（§4.2）；按 §4.3 比对取舍后删掉多余副本 |
| WebDAV 报 401 | 用户名 / 密码不对；坚果云必须用「第三方应用密码」而非网页登录密码；NAS 账号需在 WebDAV 允许列表内 |
| WebDAV 一直转圈超时 | base URL 写错（最常见：Nextcloud 漏了 `/remote.php/dav/files/用户名/` 后缀，或端口不对）；公司网络 / 防火墙挡住了 NAS 端口 |
| Android 选了目录但不生效 | Syncthing app 需保持后台运行（电池优化加白名单）；Chrome 每次冷启动可能要重新授权目录 |
| 移动端找不到「选择同步目录」 | Safari / Firefox 不支持文件夹访问，走 §2.7 手动上传 / 下载降级 |

## 6. 边界声明

- **官方不提供服务器**：同步流量只发生在「你的设备 ↔ 你的 Syncthing 网络 / 你的 WebDAV 服务器」之间。
- **官方不接触你的数据**：没有账号、没有中转、没有日志，也就无从接触或审查任何文档内容。
- **默认零外网**：未配置任何同步通道时，同步模块完全静默，不发任何网络请求。
- **不是实时云端协作**：本功能是文件级、最终一致的跨设备同步；多人同时实时编辑仍仅限同一浏览器的多个标签页。
